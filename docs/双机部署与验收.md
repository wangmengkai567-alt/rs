# 双机部署与验收

A 机运行配置服务器、路由、FastAPI 和 `shard1`，B 机只运行 `shard2`。验收需要两台电脑各用自己的 Docker 引擎和本地数据卷。B 机需要项目代码、Docker Compose 和 PowerShell，无需复制原始签到文件或运行 Python。

| 电脑 | 向对端开放的局域网 TCP 端口 | 存储与服务 |
| --- | --- | --- |
| A | 27011、27019 | `shard1`、配置服务器。路由 `127.0.0.1:27017` 和 API `127.0.0.1:8000` 供 A 机本地使用 |
| B | 27021 | `shard2` 与本地数据卷 |

## 两台电脑的准备

1. 两台电脑接入可互相访问的局域网，启动各自的 Docker 引擎。在 Windows 使用 Docker Desktop 的 Linux 容器模式，执行 `docker compose version` 和 `docker info` 确认可用。
2. 将同一版本的项目代码放到两台电脑。首次配置时，各自在仓库根目录把 `.env.example` 复制为 `.env`。编辑两份 `.env`，填入相同的一对真实局域网 IPv4。下面的地址只是示例。

   ~~~dotenv
   GOWALLA_A_IP=192.168.1.20
   GOWALLA_B_IP=192.168.1.21
   ~~~

3. 若 Windows 防火墙拦截，分别用管理员 PowerShell 为对端地址开放上表列出的端口。以下示例用于 Windows 的专用网络，先替换 IP。在实际使用的网络接口上确认网络类别和已有入站规则。

   **A 机执行**

   ~~~powershell
   New-NetFirewallRule -DisplayName "Gowalla from B" -Direction Inbound -Action Allow -Profile Private -Protocol TCP -LocalAddress 192.168.1.20 -LocalPort 27011,27019 -RemoteAddress 192.168.1.21
   ~~~

   **B 机执行**

   ~~~powershell
   New-NetFirewallRule -DisplayName "Gowalla from A" -Direction Inbound -Action Allow -Profile Private -Protocol TCP -LocalAddress 192.168.1.21 -LocalPort 27021 -RemoteAddress 192.168.1.20
   ~~~

该课程配置用于受控局域网。数据库端口只允许对端电脑访问。Compose 内部使用 `gowalla-cfg`、`gowalla-shard1`、`gowalla-shard2` 作为稳定的副本集成员名，由两份配置负责本地解析与跨主机地址映射。宿主机的 `hosts` 文件无需编辑。[MongoDB 分片集群部署](https://www.mongodb.com/docs/v7.0/tutorial/deploy-shard-cluster/) · [Docker Compose 服务配置](https://docs.docker.com/reference/compose-file/services/)

## 启动与全量导入

### B 机先启动 shard2

在 B 机项目根目录执行。

~~~powershell
docker compose -f compose.peer.yaml up -d
docker compose -f compose.peer.yaml ps
~~~

此时容器可以处于运行状态，副本集由 A 机的初始化任务统一创建。保持 B 机在线。请 A 机确认能访问 B 的 TCP 27021，Windows 上可用以下命令，将地址替换为 B 的实际 IP。

~~~powershell
Test-NetConnection 192.168.1.21 -Port 27021
~~~

### A 机初始化集群并导入

如果 A 机的旧单机项目仍占用 27017，先查看旧 Compose 项目，再停止其中占用该端口的旧路由容器。旧项目 `gowalla-course` 与双机项目 `gowalla-course-a`、`gowalla-course-b` 使用不同的数据卷。

~~~powershell
docker ps --filter "label=com.docker.compose.project=gowalla-course"
~~~

在 A 机项目根目录执行。初始化成功时，`replica-init` 和 `sharding-init` 均以状态码 0 结束。

~~~powershell
docker compose up -d
docker compose wait sharding-init
docker compose ps -a
~~~

如果初始化未完成，先核对两份 `.env` 的地址，在 B 机用 `Test-NetConnection` 分别验证到 A 的 27011 和 27019，再查看 `docker compose logs replica-init mongos sharding-init`。TCP 连通后再重试初始化。

随后在 A 机按 [README 的清洗和导入步骤](../README.md#在-a-机清洗导入与启动)执行至导入成功。A 机可启动 FastAPI，通过本机页面演示。B 的数据由路由写入其本地分片。

## B 机独立采证

等 A 机通知全量导入完成后，在 B 机本地终端执行。

~~~powershell
.\deploy\Verify-Distribution.ps1 -Peer -OutputFile .\output\evidence-b.json
~~~

脚本通过 B 机本地 Docker 引擎进入 `shard2` 容器，绕过 `mongos`，直连本容器的 MongoDB 主节点。它保存 B 机的主机名、局域网 IPv4、Docker 引擎 ID、容器 ID、本地卷名、副本集身份、`gowalla.checkins` 的精确记录数和一条真实样本记录。成功条件是 `replica_set` 为 `shard2`、`documents` 大于零。把生成的 `output/evidence-b.json` 交给 A 机。

需要现场展示直连结果时，也可在 B 机当场执行下面的只读命令。B 机终端的 `hostname` 与直连输出可一并截图。

~~~powershell
hostname
docker info --format '{{.ID}}'
docker compose -f compose.peer.yaml exec -T shard2 mongosh 'mongodb://127.0.0.1:27021/?directConnection=true' --quiet --file /scripts/verify_local_shard.js
~~~

## A 机对账与通过标准

把 B 机的 JSON 放到 A 机项目下的 `output/evidence-b.json`，然后运行。

~~~powershell
.\deploy\Verify-Distribution.ps1 -PeerEvidence .\output\evidence-b.json -OutputFile .\output\dual-host-verification.json
~~~

脚本检查以下条件，全部满足才写入 `status: passed`。

| 核验项 | 通过标准 |
| --- | --- |
| 宿主机和节点身份 | A、B 的局域网地址不同，Docker 引擎 ID 不同，端口发布在各自宿主机地址。两个节点分别为 `shard1` 和 `shard2`，各自有可写本地数据卷 |
| 跨机直连 | A 机上的容器通过 B 的局域网地址直连 `shard2`，计数和样本与 B 机本地证据一致 |
| 双节点存储 | 直连两个分片的计数均大于零，分别等于 `mongos` 报告的持有文档数，两片孤立文档数均为零 |
| 全量对账 | 附件读取 6,442,892 条，拒收 765 条。两个分片的直连计数之和、`mongos` 精确计数和清洗输出均为 6,442,127 条 |
| 实际查询 | 用户 0 的轨迹共 225 条，执行计划只访问一个分片。奥斯汀范围查询访问两片，并返回源文件第 1 行 |

提交证据可保留 `evidence-b.json`、`dual-host-verification.json` 和 A 机的 `quality_report.json`。最终 JSON 包含两台电脑的证据和真实查询执行计划。分片计数与查询结果以本轮实测值为准。[MongoDB 数据分布聚合文档](https://www.mongodb.com/docs/v7.0/reference/operator/aggregation/shardeddatadistribution/)

### 现场可追加中断复测

完成一次成功验收后，可在 B 机暂时停止 `shard2`，验证 A 的跨片请求无法返回完整结果。在 A 机先确认完整计数成功，再让 B 执行停止命令。停止期间重跑下列 A 机计数命令，应返回 MongoDB 错误或超时。

~~~powershell
# B 机暂停 shard2
docker compose -f compose.peer.yaml stop shard2

# A 机检查需要两片参与的全量计数
docker compose exec -T mongos mongosh --quiet --eval 'print(db.getSiblingDB("gowalla").checkins.countDocuments({}, {maxTimeMS: 5000}))'
~~~

随后 B 机执行 `docker compose -f compose.peer.yaml up -d shard2`。等容器内副本集重新成为主节点后，B 机重新采证，A 机再次运行双机验收，计数应恢复到 6,442,127。已导入的数据保存在两台电脑各自的卷里。
